# Phase 3: Picking the question

This is the core judgment of the whole job. Do not skip it, and do not let it default to "overview".

Before building anything, decide the single question the dashboard answers, and decide it as the OWNER would, not as an analyst. The strongest question is almost always **where value crosses the boundary of the business and could be stuck, late, or leaking**: money invoiced but not collected, bills owed, work promised but not delivered, stock committed, bookings unconfirmed, members lapsing.

Rank the candidates by:

1. How much money hangs on the answer.
2. Whether this data can actually answer it.

Put the chosen question, in the owner's own vocabulary, at the top of the page as its title.

## When the data cannot carry an urgent question

If the data genuinely cannot support an urgent question (no dates, no amounts), **do not fake one**. Build the honest smaller thing:

- A clean snapshot of the business as recorded.
- A prominent section titled "what to start recording so this page can warn you", listing the 1 to 3 missing columns that would unlock real alerts next time.

This smaller page is not a failure. For an owner whose data is a single messy sheet, knowing exactly which columns to start filling is worth more than a decorated page pretending to answers it does not have.
